# Семейное древо

React + Vite + TypeScript приложение для ведения семейных деревьев. Статический frontend публикуется на GitHub Pages, а Supabase предоставляет Auth, PostgreSQL и приватное файловое хранилище.

## Возможности

- Регистрация, вход, выход и восстановление пароля через Supabase Auth.
- Несколько семейных деревьев на аккаунт.
- Создание и редактирование персон: имя, фамилия, даты, пол, место рождения, биография, фото.
- Интерактивный холст: панорамирование, масштабирование, мини-карта и автоматическая раскладка.
- Родственные связи: родитель → ребёнок, брат/сестра, супруги.
- Фото с клиентским сжатием; приватный Storage и временные подписанные URL.
- Zod + React Hook Form для валидации, понятные уведомления, адаптивный интерфейс и тёмная тема.
- RLS-политики изолируют деревья разных аккаунтов.

> Это стартовый production-oriented проект, но перед использованием с реальными семейными данными проверьте настройки Auth, правила RLS и приватность фотографий. Не добавляйте секретный `service_role` ключ в frontend.

## 1. Что понадобится

- Node.js 22 LTS (или актуальная LTS-версия) и npm.
- Бесплатный аккаунт GitHub.
- Бесплатный проект Supabase.

## 2. Создайте проект Supabase

1. Откройте [Supabase](https://supabase.com/) и создайте проект на Free plan.
2. Сохраните пароль базы в надёжном месте; приложению он не нужен.
3. В проекте откройте **SQL Editor → New query**.
4. Скопируйте и выполните весь файл `supabase/migrations/001_family_tree.sql`.
5. Откройте **Project Settings → API** (названия разделов могут измениться).
6. Скопируйте Project URL и publishable key (или legacy anon key). Никогда не используйте `service_role`/secret key в браузере.
7. В **Authentication → URL Configuration** задайте Site URL как URL GitHub Pages, например `https://USERNAME.github.io/REPO/`, и добавьте этот URL в Redirect URLs. Для локальной разработки добавьте `http://localhost:5173/**`.
8. Если включено подтверждение email, регистрация требует перехода по ссылке из письма. Для восстановления пароля Supabase также должен разрешать URL сайта в Redirect URLs.

### Переменные окружения

Создайте `.env` в корне проекта, скопировав `.env.example`:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY
VITE_BASE_PATH=/
```

Не коммитьте `.env`. Переменные с префиксом `VITE_` попадут в собранный браузерный код; поэтому туда разрешено помещать только публичный publishable/anon ключ. Защиту обеспечивает RLS.

## 3. Запуск локально

```bash
npm install
npm run dev
```

Откройте URL, который покажет Vite (обычно `http://localhost:5173`). Если изменили `.env`, перезапустите dev-сервер.

Проверка production-сборки:

```bash
npm run build
npm run preview
```

## 4. Загрузка в GitHub

1. Создайте новый репозиторий на GitHub, например `semeinoe-drevo`.
2. Скопируйте в него файлы проекта.
3. Создайте `main` и отправьте коммит:

```bash
git init
git add .
git commit -m "Initial family tree app"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

## 5. Настройте GitHub Pages и авто-деплой

1. В репозитории откройте **Settings → Secrets and variables → Actions**.
2. Добавьте repository secrets:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
3. Откройте **Settings → Pages** и выберите **GitHub Actions** в разделе Build and deployment.
4. Убедитесь, что workflow находится в `.github/workflows/deploy.yml`.
5. Отправьте коммит в ветку `main` или запустите workflow через **Actions → Deploy to GitHub Pages → Run workflow**.
6. После успешного workflow сайт появится по адресу `https://USERNAME.github.io/REPO/`.

`vite.config.ts` использует `VITE_BASE_PATH`, а workflow автоматически устанавливает `/${{ github.event.repository.name }}/`. Это важно для репозиторного URL GitHub Pages. Для пользовательского репозитория `USERNAME.github.io` можно поменять base на `/`.

## 6. Как устроены данные

- `family_trees`: дерево и владелец (`user_id`).
- `persons`: карточки персон; при удалении дерева персоны удаляются каскадно.
- `relationships`: родственные связи.
- `family-photos`: приватный Storage-бакет. Путь к файлу хранится в `persons.photo_path`, а приложение запрашивает временную подписанную ссылку.

Тип `parent` хранит направление **от родителя к ребёнку**. `sibling` и `spouse` — отдельные связи. Дяди/тёти напрямую не хранятся: они выводятся из графа родителей, а при необходимости можно добавить отдельный тип связи и UI для него.

## 7. Бесплатные лимиты Supabase

Лимиты меняются, поэтому сверяйте актуальные цифры на [официальной странице тарифов](https://supabase.com/pricing). По опубликованным лимитам Free:
- 2 активных проекта на аккаунт/организацию (неиспользуемые проекты могут ставиться на паузу).
- 500 МБ базы данных на проект.
- 1 ГБ файлового Storage.
- 5 ГБ исходящего трафика (egress) и 5 ГБ cached egress.
- До 50 000 ежемесячно активных пользователей Auth.
- Free-проект может быть приостановлен после недели бездействия.

Примерная вместимость фотографий в 1 ГБ:
- при среднем сжатом фото 200 КБ — около 5 000 фото;
- при 500 КБ — около 2 000 фото;
- при 800 КБ — около 1 250 фото.

Это грубая оценка без учёта служебных данных и других файлов. Число персон не имеет фиксированного лимита на уровне приложения: оно зависит от размера записей, индексов и того, сколько места занимают все таблицы в пределах 500 МБ. Для небольшого семейного архива бесплатного тарифа обычно достаточно.

## 8. Важные замечания

- Семейные сведения и фото — чувствительные данные. Используйте приватный Storage и не публикуйте публичные ссылки.
- В текущей версии фотографии загружаются в приватный бакет и открываются через временные URL. URL может истечь примерно через час; перезагрузка страницы обновляет его.
- Удаление персоны удаляет связанные строки relationships благодаря `ON DELETE CASCADE`. Сам объект фото в Storage автоматически не удаляется; при большом архиве добавьте отдельную процедуру очистки.
- В текущей версии нет совместного редактирования между несколькими аккаунтами, экспорта GEDCOM/PDF и автоматического определения дядей/тётей. Это можно добавить отдельными этапами.
- GitHub Pages отдаёт frontend публично; приватность данных обеспечивают Supabase Auth, RLS и приватный Storage.
